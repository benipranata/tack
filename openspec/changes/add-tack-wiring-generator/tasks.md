## 1. Project scaffolding

- [ ] 1.1 Create the package layout: `internal/config` (tack.yaml parsing/validation), `internal/scan`
      (provider discovery via go/packages + go/types), `internal/resolve` (per-type resolution and
      ambiguity), `internal/gen` (code emission), `cmd/tack` (CLI entry point).
- [ ] 1.2 Add `golang.org/x/tools` (`go/packages`, `imports`) as a module dependency.

## 2. Config loading & validation

- [ ] 2.1 Define the `tack.yaml` schema struct (`providers`, `packages -> interface -> name/output/localScan`)
      with a strict decoder that rejects unknown keys.
- [ ] 2.2 Implement config discovery: walk up from the working directory looking for `tack.yaml`;
      support `--config <path>` as a direct override that skips discovery.
- [ ] 2.3 Resolve provider/package paths as module-relative directories against the `go.mod` location.
- [ ] 2.4 Unit test: a config with a removed `providers:` key nested under a package or interface
      entry fails validation, naming the key and its location.

## 3. Provider scanning

- [ ] 3.1 Implement the provider-signature qualification check
      (`func(context.Context) (T, func(), error)`) against `go/types` function signatures.
- [ ] 3.2 Build the global provider index (type → provider function) from every package listed in
      `providers:`, erroring on same-scope ambiguity (two qualifying functions for one type).
- [ ] 3.3 Build a per-target-directory local provider index from an interface's own package, using
      the same ambiguity rule.
- [ ] 3.4 Unit test: a `Provide`-prefixed function with a mismatched signature is not indexed and
      does not error on its own.

## 4. Resolution

- [ ] 4.1 Implement per-interface resolution: for each accessor method's result type, consult local
      scope first (unless `localScan: false`), then global; on failure, record the unsatisfied type
      plus any near-miss `Provide*` candidates for the error message.
- [ ] 4.2 Implement interface-shape validation: every method must take zero parameters and return
      exactly one result, else a hard error naming the offending method.
- [ ] 4.3 Implement non-nilable dependency type rejection for accessor results.
- [ ] 4.4 Unit test: local-beats-global shadowing is per-type, not package-wide (mirrors case-01's
      `*c.C` vs. `*d.D` split).
- [ ] 4.5 Unit test: `localScan: false` on one interface does not affect a sibling interface
      configured in the same directory.
- [ ] 4.6 Unit test: a directory listed in both the global `providers:` list and as an interface's
      own package resolves without a spurious ambiguity error.

## 5. Code emission

- [ ] 5.1 Build the identifier allocator: seeded with `ctx`, `cleanup`, `cleanups`, `err`, every
      import alias, Go keywords, and predeclared identifiers; hands out names and appends a numeric
      counter on collision.
- [ ] 5.2 Write the `text/template` templates for the constructor, private struct, accessor methods,
      and the test-helper struct + constructor, matching case-01's shape, including the
      `// Code generated by tack. DO NOT EDIT.` header.
- [ ] 5.3 Run `golang.org/x/tools/imports` over the templated output to resolve and format the import
      block (qualified provider imports, unqualified local calls, `context`/`fmt`/`testing`).
- [ ] 5.4 Implement default output filename derivation (`lower(name)_lower(interface)_gen.go`) for
      interface entries with no `output:` key.
- [ ] 5.5 Implement stale-output deletion: remove every configured output file for a target package
      before calling `packages.Load` on it.
- [ ] 5.6 Unit test: the identifier allocator suffixes a colliding derived name (e.g. a method named
      `Cleanup`) instead of reusing it, and the resulting file still compiles.

## 6. CLI

- [ ] 6.1 Implement `cmd/tack` argument parsing with stdlib `flag`: bare invocation and `generate`
      as aliases, `init` as a subcommand, `--config` as the only flag.
- [ ] 6.2 Wire `tack` / `tack generate` to run discovery/load → scan → resolve → emit for every
      configured interface, exiting non-zero with the specific error on any failure and leaving no
      partially written output file for the interface that failed.
- [ ] 6.3 Implement `tack init`: write a starter `tack.yaml` if none exists in the current directory;
      if one already exists, leave it untouched and report that instead of overwriting.
